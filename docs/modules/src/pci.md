# pci.asm
[`src/pci.asm`](../../../src/pci.asm) — 345 lines, 7 entry points.

Type 1 PCI configuration access and a minimal device scan.

Address form used throughout: EDI = 0x80000000 | bus<<16 | dev<<11 | fn<<8 | (register & 0xFC)

| `pci_bar_addr` | [111](../../../src/pci.asm#L111) | EDI = config address of the BAR, returns the 64-bit base in RAX with the type bits stripped. Handles the 64-bit BAR form. |
| `pci_enable` | [140](../../../src/pci.asm#L140) | EDI = config address of the device; turn on I/O space, memory space and bus mastering. |
| `pci_bar_size` | [164](../../../src/pci.asm#L164) | EDI = config address of a BAR. Returns EAX = size in bytes (0 if the BAR is unimplemented) and EDX = the value read back, whose low bits carry the BAR type. The BAR is left holding the all-ones probe value; the caller is expected to write a real base next. Only the low 32 bits are sized. A BAR wider than 4 GiB could not be placed in the window this firmware hands out anyway. |
| `pci_assign_resources` | [201](../../../src/pci.asm#L201) | give every device on bus 0 a home. QEMU hands the firmware a machine whose BARs are all zero: assigning them is firmware's job, and until it happens the framebuffer has no address. Each BAR is sized by writing all ones, then placed in the MMIO or I/O window at its natural alignment. Bus 0 only, and type 0 headers only — the QEMU machines this targets have no PCI-to-PCI bridges unless one is asked for on the command line. |
